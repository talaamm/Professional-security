  Key design decisions worth your review:
  1. Admin lock-out is enforced by the DB trigger, not client code
     — handle_new_user() always inserts role = 'employee'
     regardless of signup metadata, so there's no client path to
     self-register as admin/super_admin. I didn't add redundant
     client-side role logic since the DB is already authoritative.
  2. Inactive-account check runs both at login and on every app
     restart (in AuthGate), not just at sign-in — so a profile
     deactivated while a device still holds a session gets signed
     out next launch.
  3. "Forgot password" is informational only (matches your own
     mockup: "contact your system administrator"), not a real email
     flow — since @internal.app addresses can't receive mail.
     Actual reset is an admin action for Phase 7.
  4. Skipped the mockup's device-registration and "Remember me"
     screens — not requested for this phase and no backend behavior
     to attach to "Remember me" (Supabase always persists sessions
     the same way).
